# 來源標示 (Attribution)

## 借用的程式碼

**無。** `scripts/reader.html` 與 `scripts/pdf_to_paper.py` 均為自行撰寫，
未複製任何外部專案的程式碼，也未內嵌任何第三方 JavaScript 函式庫。

### 關於 Rangy 與 mark.js（原本預計借用，實際未採用）

建置前盤點時，曾規劃採用：
- **Rangy**（Tim Down，MIT）的 Highlighter Module — 其 `serialize()`／`deserialize()`
  可將頁面高亮序列化保存，是「標記可持久化」的成熟方案。
- **mark.js**（MIT）— 文字高亮 API。

**實作時判斷不需要，因此未使用。** 理由：Rangy 的價值在於處理**任意、不受控的 DOM**
（例如瀏覽器擴充套件要標記別人的網頁）。本閱讀器的段落 DOM 完全由自己的 `render()`
產生、結構受控，因此高亮序列化只需記錄「段落索引 + 欄位 + 純文字字元起訖位移」
（`{i, side, s, e, cat}`），用瀏覽器原生 Selection / Range API 加一個
TreeWalker 計算位移即可完成，約 20 行程式碼。

引入 1,000+ 行的外部函式庫來解一個 20 行的問題，只會增加相依與供應鏈風險。
**因此本技能維持零第三方相依、完全離線可用。**

謹此說明：雖未採用，Rangy 對「DOM 高亮序列化」這個問題的解法
（以文字節點位移而非 DOM 路徑作為錨點）確實啟發了本實作的方向。
若日後需要支援任意 DOM 的標記，Rangy 仍是首選方案。
