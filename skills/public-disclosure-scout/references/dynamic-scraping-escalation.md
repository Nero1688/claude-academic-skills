# 動態網站抓取升級階梯(遇到 requests 抓不到時)

多數官方揭露/資料頁用 `requests` + 對的 headers 就抓得到。但有些頁面
(部分 MOPS 查詢、司法院裁判書、某些 JS 前端渲染的資料入口)內容是 JavaScript
動態載入的,`requests` 只會拿到空殼。此時**由輕到重逐級升級**,不要一步跳到重工具,
也不要放棄合規紅線。

## 升級階梯(能低不高)

| 級 | 手段 | 何時用 | 成本 |
|---|---|---|---|
| 1 | `requests` + 正確 headers/session | 靜態 HTML、多數 OpenAPI | 最低 |
| 2 | 找背後的 API/AJAX 端點 | 頁面 JS 去打某個 JSON 端點——直接打那個端點 | 低(最划算,優先試) |
| 3 | 官方批次檔/OpenData 下載 | 站方有提供 CSV/ZIP 批次 | 低 |
| 4 | 無頭瀏覽器渲染 | 內容真的靠 JS 才生得出來,且無 API 可用 | 高(重依賴) |
| 5 | 人工/半自動 | 有驗證碼、明確禁止自動抓、量小 | 人力 |

**第 2 級最常被忽略但最有效**:打開瀏覽器開發者工具 → Network,看頁面 JS 實際去打
哪個端點回 JSON,直接打那個(乾淨、快、穩),往往免掉無頭瀏覽器。

## 第 4 級:無頭瀏覽器(需要時的正確做法)

要渲染 JS 才拿得到內容時,用無頭瀏覽器工具。成熟選項如
[crawl4ai](https://github.com/unclecode/crawl4ai)(Apache 2.0,Playwright 底層,
可輸出乾淨 markdown、支援 CSS/XPath 抽取)或直接用 Playwright。
概念上本升級階梯借鏡 crawl4ai「把網頁轉成 LLM 可讀結構」的思路。

務實提醒:
- 這類工具會**下載瀏覽器核心(數百 MB)**,是重依賴——只在第 1-3 級都不行時才上。
- 抓下來的內容仍要走本 skill 的品質檢查(更正/撤銷、抽樣核對)。

## 🚫 合規紅線(比能不能抓更重要)

無論用哪一級,以下是**研究倫理與法遵的硬底線**,不因工具方便而放寬:
1. **守 robots.txt 與服務條款**:站方明示禁止自動抓取就停,改用官方批次或申請管道。
2. **禮貌抓取**:請求間隔數秒、量小、離峰、不打爆站台。
3. **🚫 禁用反偵測/隱身功能**:crawl4ai 等工具有 stealth mode / 反 bot 偵測 /
   代理輪換等功能——**學術研究一律不使用**。繞過站方的 bot 偵測=規避其明示的
   使用意願,是研究倫理問題,也可能違法。抓不到就升級到「官方管道/申請/人工」,
   不是升級到「躲過偵測」。
4. **驗證碼不繞過**:遇 CAPTCHA 表示站方要求人工,尊重之。
5. **個資去識別**:揭露文件含自然人姓名者,研究呈現去識別化。

一句話:**升級的是「技術能力」,不是「規避程度」。** 合規紅線在任何級別都不變。
