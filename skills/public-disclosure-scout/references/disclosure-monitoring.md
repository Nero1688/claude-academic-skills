# 揭露頁變更監測與引用永久性

本檔回答兩個相關但不同的問題：(1) 怎麼知道 MOPS／公司 IR 頁的內容變了（變更監測）；
(2) 論文引用的網頁，審稿人三年後點開連結還在不在（引用永久性）。兩者用同一套
工具串起來：偵測到變更 → 立刻存檔 → 論文引用附存檔連結。

## 一、為什麼這是頂刊等級的問題，不是技術細節

量化管理／財金論文引用網頁來源的情況越來越多：MOPS 重大訊息公告、公司投資人
關係頁的新聞稿、政府統計頁的方法說明、法規條文的官網頁面。這些頁面**沒有 DOI，
沒有版本控管，站方可以任何時候改版、下架或搬遷網址**。與期刊論文（有 DOI，
CrossRef 可查證）不同，網頁引用的可驗證性完全繫於「你抓的那一刻」是否有留底。

**頂刊落差**：審稿人或資料編輯點開論文附註或參考文獻裡的網址，得到 404 或
「找不到網頁」，是審稿意見常見的扣分項——不是因為內容錯，而是因為**讀者無法
驗證你引用的東西曾經存在過**。少數期刊（如要求可重現性聲明的財金/會計期刊）
已明文要求網頁引用附存檔連結。

**對策（本 skill 的立場）**：論文方法節或參考文獻中，**每一個網頁來源都應附
Wayback 快照連結，或至少附「擷取日期＋內容雜湊」供事後查核**；查不到、存不了
的，論文中要老實標「存檔失敗，僅記錄擷取日期」，不能假裝存了。

## 二、MOPS／公司 IR 頁的變更監測設計

台灣公司治理與揭露研究常需要長期追蹤同一批頁面（如特定公司的 IR 新聞頁、
MOPS 重大訊息查詢結果、公司治理專區）。監測設計三層：

### 1. 內容雜湊比對（偵測「變了沒」）

- 每次排程抓取後，對頁面正文（去除時間戳、廣告版位等易變雜訊區塊後的主體）
  算一次雜湊（SHA-256 即可，不需要加密雜湊等級的強度，只是拿來比對「變了沒」）。
- 雜湊不同 → 判定內容有變更 → 觸發存檔（見下）。
- 雜湊相同 → 不必重複存檔，省頻寬也省對站台的負擔。
- 本 skill 的 `scripts/archive_url.py` 提供 `hash` 子指令，但雜湊的對象是
  **已被 Wayback 收錄的快照內容**（見腳本檔頭說明的網路範圍限制）；即時頁面本身
  的雜湊比對，要靠各站台專用的抓取腳本（如 台灣官方統計的撈取腳本 或使用者
  私有的 MOPS 工具）在其獲准連線的網域內完成，本工具接手「存檔」那一棒。

### 2. 排程頻率與禮貌間隔

| 頁面類型 | 建議頻率 | 理由 |
|---|---|---|
| MOPS 重大訊息查詢 | 每日一次 | 重訊即時性高，但站方限制批次查詢，日頻已足夠學術用途 |
| 公司 IR 新聞頁 | 每週一次 | 更新頻率低於重大訊息 |
| 年報／財報 PDF 頁面 | 事件觸發（公告當週） | 固定 URL 樣式，公告後才會出現，天天輪詢浪費資源 |
| 政府統計方法說明頁 | 每季一次 | 內容極少變動，但一旦變動（如基期調整）影響研究定義 |

不論頻率，**單次請求間隔至少數秒**（同 `dynamic-scraping-escalation.md` 的合規紅線），
排程整體離峰執行，不對單一站台造成負擔集中。

### 3. 變更即存檔（page-monitoring 概念）

監測到雜湊變更時，**立刻**呼叫 `archive_url.py save <url>` 排入存檔（不是累積到
月底一次補），理由：(a) 內容一旦被站方覆蓋，事後再想存檔只能存到新版本，舊版本
就永久遺失；(b) Wayback 的存檔請求本身有限流，變更當下存一次比事後回補容易。
此概念借鏡自 `jamditis/claude-skills-journalism`（MIT，見 `ATTRIBUTION.md`）的
「頁面變更觸發存檔」思路——**只借用概念，未採用其程式碼，也未採用其付費牆
（paywall）相關子技能**（付費牆繞過涉及規避站方存取控制，不屬本 skill 的合規紅線
範圍內，見 `dynamic-scraping-escalation.md` 的🚫清單）。

## 三、引用永久性：論文怎麼寫

### 1. 一律附存檔連結或存檔日期

論文引用網頁來源時，建議格式：

```
公開資訊觀測站(2026)。〈某公司114年度重大訊息：董事會決議通過...〉。取自
https://mops.twse.com.tw/mops/...（存檔：https://web.archive.org/web/20260920.../...，
擷取日期：2026-09-20）
```

存不到（Wayback 尚未收錄、存檔請求被限流又來不及重試）時，**至少寫擷取日期與
內容雜湊**，不要略過這一步：

```
（未能於投稿前完成 Wayback 存檔，擷取日期：2026-09-20，內容 SHA-256：
a1b2c3.../供事後查核）
```

### 2. 三種常見台灣情境的具體做法

**(a) MOPS 重大訊息**：MOPS 重訊本身有官方「發言日期＋序號」可引用（如
「114年09月20日 16:30:00 發言人代號：1」），這組識別碼比網址本身更穩定——
**網址可能隨改版失效，但這組官方 ID 是公司法定揭露紀錄的一部分，通常可用來
在新版查詢介面重新定位**。論文中同時附官方 ID 與存檔連結最保險。

**(b) 年報 PDF**：MOPS 年報通常有固定 URL 樣式（依公司代號、年度、報告類型
組成路徑），此類固定樣式頁面**適合排程監測**（公告當週檢查是否已上線），
一旦出現就立刻存檔——PDF 本身也建議另存一份於複製包（若授權允許），
存檔連結作為「網路上曾經長這樣」的佐證，複製包內的檔案作為分析用的正本。

**(c) 政府網站（.gov.tw）TLS**：本 skill 家族抓取 .gov.tw 網站時，一律沿用
`_gov_tls.py` 的相容層寫法（只解除 `VERIFY_X509_STRICT`，完整保留憑證鏈與
主機名驗證，**不使用** `verify=False`）——存檔腳本本身不連 .gov.tw（見下方
網路範圍說明），但**觸發存檔的來源監測腳本**若要連 .gov.tw 取得頁面內容，
必須沿用這個慣例，不要為了圖方便另外寫一個關掉憑證驗證的版本。

### 3. 頂刊落差：審稿人點開連結 404 時的對策

發生順序通常是：(1) 投稿時網頁引用尚可點開 → (2) 審稿期間（數月至一年）
站方改版或下架 → (3) 審稿人或讀者事後點開得到 404 → (4) 若無存檔連結，
審稿人無法驗證引用真實性，可能質疑資料來源可信度，即使原始論述完全正確。

對策分三層：
1. **投稿當下**：每個網頁引用都附 Wayback 快照連結（本檔第二、三節的流程）。
2. **審稿期間**：長審稿週期（管理/財金頂刊常見 6 個月以上）建議在改版/大修
   階段**重新查一次所有網頁引用是否仍可點開**，補存新變化。
3. **無法存檔時的誠實揭露**：`archive_url.py save` 遇 429/500 時會印出三條
   替代路徑（稍後重試／瀏覽器手動存檔／使用者自備金鑰走 SPN2）；若最終仍未能
   存檔，論文附註誠實寫「存檔請求受限流未成功，僅以擷取日期與內容雜湊佐證」，
   **不可謊稱已存檔**（違反第6條數字零容忍與第9條猜測標註紀律）。

## 四、Wayback Machine 端點實測（本次建置的一手記錄）

以下由本專案主對話於 **2026-09-20** 對真實端點逐一實測，供腳本設計與後續維護
依據；若日後端點行為改變，以最新實測覆蓋本節，並更新日期。

| 端點 | 用途 | 實測結果 | 狀態 |
|---|---|---|---|
| `https://web.archive.org/cdx/search/cdx?url=<domain>&limit=N&output=json` | 查快照清單 | **HTTP 200**，回傳含 urlkey／timestamp／original／statuscode 的快照清單 | ✅ 可用，`lookup` 採用 |
| `https://archive.org/wayback/available?url=<url>` | 查單一網址是否有快照 | 帶 UA 重試仍 **429 Too Many Requests** | ❌ 本工具不使用 |
| `https://web.archive.org/save/<url>`（匿名 Save Page Now） | 觸發存檔 | **429／500** | ⚠️ `save` 會嘗試，遇限流印替代路徑 |
| SPN2 認證端點（帶 `archive.org` S3 金鑰的 `Authorization: LOW key:secret`） | 認證後觸發存檔，理論上限流較寬鬆 | **本次未實測** | ⚠️ 待確認，腳本僅在偵測到金鑰時盡力嘗試，明確標示未驗證 |

補充（`archive_url.py` 實作與測試過程中另外觀察到，同日稍晚）：CDX 端點本身
會**間歇性回應 503 "Internet Archive: Temporarily Offline"**（整站短暫離線，
非本工具或本次查詢寫錯），重試數次後可恢復取得 200。這不推翻上表「CDX 可用」
的結論，但代表**任何呼叫 CDX 的程式都應內建重試退避**，`archive_url.py` 已如此
實作（預設重試 3 次、指數退避）。單次 503 不代表端點失效，連續多次重試仍失敗
才應懷疑端點本身或網路環境有問題。

## 六、紅線（沿用家族精神）

1. 不假裝存檔成功——`save` 失敗就老實回報 429/500，不在論文中宣稱「已存檔」。
2. 存檔請求守禮貌間隔，不因為批次處理大量引用就高頻打 Wayback。
3. 引用永久性交代要包含擷取日期；**存檔連結會過期或初次未收錄，日期不會**。
4. SPN2 金鑰只讀環境變數，不寫死、不進版本控制、不進 CSV 記錄檔。
