# 審查人視角三軸自評量規：創新性／可行性／申請人能力

> 對應 SKILL.md「審查人視角自評(產出前必跑)」。三軸各給 1–5 分，低於 4 分的軸
> 先補強再送。本量規的分數是**自評工具的相對量尺**，不是國科會官方評分標準
> ——官方審查標準與配分比重【以當年度公告為準】，本量規僅供申請人自我檢查用。

## 軸一：創新性(Innovation)

| 分數 | 描述 |
|---|---|
| 5 | 缺口論證同時交代「這缺口是真的」與「填了有人在乎」；能具體指出現有文獻的
理論或方法限制，並說明本計畫的解方如何超越既有做法，而非只是換個資料集重跑 |
| 4 | 缺口論證清楚，但「為何重要」的說理稍弱，或創新處主要是方法上的漸進改良 |
| 3 | 有指出文獻缺口，但流於「過去研究較少關注此議題」的一般性陳述，未具體化 |
| 2 | 缺口論證僅為「沒人做過」，未回答為何值得投資資源填補 |
| 1 | 看不出與既有文獻的差異，或研究問題已被既有文獻大量處理 |

**常見扣分點**：
- 缺口論證只有「沒人做過」沒有「為何重要」——這是最高頻的扣分模式。
- 創新點包裝過度：把既有方法套用到新資料集，卻宣稱是理論創新。
- 文獻回顧列了很多篇但看不出「所以缺口在哪裡」的邏輯線。

## 軸二：可行性(Feasibility)

| 分數 | 描述 |
|---|---|
| 5 | 資料可得性有具體證明(授權在手或取得時程明確可信)、方法設定審查人一看就知道
申請人懂怎麼做、多年期工作規劃前後負荷合理、風險與備案有交代 |
| 4 | 主要方法與資料交代清楚，但時程或工作量分配稍有前輕後重的疑慮 |
| 3 | 方法設定籠統(如僅寫「控制內生性」卻不說明用什麼識別策略)，資料可得性
未附具體證明 |
| 2 | 資料尚未取得且無明確取得計畫，或方法與研究問題明顯不對應 |
| 1 | 看不出申請人有能力在計畫期程內完成所述工作 |

**常見扣分點**：
- 資料可得性無證明——尤其授權資料(如 TEJ)只說「將會取得」，審查人最怕
  這種資料拿不到的風險。
- 多年期計畫工作量前輕後重：第一年期幾乎沒有具體產出，把所有困難工作
  堆到最後一年期。
- 識別策略描述空泛，讓審查人懷疑申請人是否真正理解方法論的挑戰所在。

## 軸三：申請人能力(Applicant Capability)

| 分數 | 描述 |
|---|---|
| 5 | 著作清單與計畫主題有清楚連貫性(過去累積的方法或資料能力直接支撐本計畫)，
且有前期成果(pilot study 或相關已發表/在審文章)佐證可行性 |
| 4 | 著作與主題大致相關，但欠缺直接對應本計畫方法的前期成果 |
| 3 | 著作清單與計畫主題關聯薄弱，需要額外說明轉換研究方向的合理性 |
| 2 | 過往紀錄與本計畫主題斷裂，且無前期成果可佐證新方向的可行性 |
| 1 | 申請人資歷與計畫所需的方法能力明顯不匹配，未提出任何彌補說明 |

**常見扣分點**：
- 著作清單與計畫主題斷裂，卻未在計畫書中主動說明「為何轉換方向、憑什麼
  能做好」——沉默不說明比誠實交代轉換理由更容易被扣分。
- 無前期成果(pilot)佐證，尤其方法本身較新穎或有操作難度時，審查人會質疑
  申請人是否真的能執行。
- 過往計畫執行紀錄（如有）未清楚交代結案情形，讓審查人無從判斷履約能力。

## 使用方式

1. 初稿完成後，逐軸對照上表描述，誠實給分（不是找最好聽的描述往上套）。
2. 任一軸低於 4 分，回到 SKILL.md 對應節次補強，不要跳過直接送件。
3. 三軸皆補強後，建議請一位非本計畫團隊成員的同儕，用同一張量規再評一次
   ——申請人自評容易對自己的論證邏輯有盲點，外部視角能抓出「審查人看不懂
   但申請人自己覺得很清楚」的落差。

## 重要提醒

本量規的分數與描述語言僅為自我檢查輔助工具，**不代表國科會官方審查配分
方式**。實際審查標準、配分比重、審查意見格式【以當年度公告與審查制度為準】，
本 skill 不代為預測審查結果或保證通過率。
