# 免費 API 學術准入檢核（清單上找到一個 API 之後，能不能進論文？）

**定位**：public-apis 這類清單是「發現層」，只告訴你有東西存在；本檔是「准入層」，
決定它能當論文主資料、只能交叉核對、只能當線索，還是不能用。
本檔只談判斷方法，不列端點；端點的實測紀錄依 SKILL.md 的路由另行維護。

---

## 一、清單三欄位怎麼讀（Auth／HTTPS／CORS）

| 欄位 | 值 | 對學術研究的意義 |
|---|---|---|
| Auth | `No` | 免註冊就能呼叫，**但不代表沒有條款**，條款照樣要讀。這欄也會過時：標 `No`、實際已改成要金鑰的情形不少見，一律以實際打過的結果為準 |
| | `apiKey` | 要註冊拿金鑰。可重現性的代價是複製者也得自己註冊；金鑰走環境變數，不進程式碼、不進複製包 |
| | `OAuth` | 綁使用者帳號授權，通常是「讀某個人帳號裡的資料」（信箱、帳戶交易、雲端文件），多半涉及個資與第三方同意。**原則上不當研究資料源**，除非有 IRB／資料使用協議 |
| | `User-Agent` | 要求在 UA 寫明身分與聯絡方式，不帶就 403。這是禮貌規範，不是金鑰 |
| HTTPS | `No` | 明文傳輸，回應被竄改也察覺不到 → 取回的數字要與 HTTPS 來源交叉核對；這條連線上不附帶任何身分資訊 |
| CORS | 任意值 | 只影響「瀏覽器裡的網頁直接呼叫」。Python／R 腳本不受 CORS 限制——**不要用 CORS 判斷能不能拿來做研究** |

## 二、一手源還是包裝層？（最常見的引用錯誤）

- 清單近年大量湧入**包裝層**：把官方資料（證券申報、勞動統計、國際組織指標）
  重新包成 API、加上「AI 摘要／AI 評分」，再免費或收費提供。2026-10-08 檢視時，
  光是美國 SEC EDGAR 這一個官方源，清單的 Finance 類就至少有五個第三方包裝服務。
- **判準只有一個：資料的產生者是誰。** API 提供者不是產生者，它就是包裝層。
- **用法**：包裝層可以用來「發現」或「方便取得」，但論文引用與資料可用性聲明
  一律回溯到產生者；產生者自己有免金鑰 API 時，直接用官方的。
- 非用包裝層不可時，先問三題：有沒有揭露來源與抓取時點？有沒有動過數值
  （單位換算、補值、季節調整）？它停止營運後，你的資料還能重建嗎？
- 「AI 摘要／AI 評分」是另一個模型的判讀，**不是資料**，不能當變數來源
  （除非研究主題就是那個模型本身）。

## 三、准入檢核表（逐項過，任一紅燈就降級用途）

1. **產生者與性質**：官方機構／國際組織／學術計畫／商業公司／個人專案。
   個人專案掛在免費託管平台上（重新部署網址就可能變）→ 只當線索。
2. **授權**：公共領域／CC0／CC BY／CC BY-NC（非商業，學術通常可用，但放進公開
   複製包要守 NC 與標示）／ODbL（衍生資料庫公開釋出時要以相同授權分享）／自訂條款／
   **未標示**——未標示不等於可自由使用，一律視為待確認。
3. **服務條款**：允不允許研究使用？允不允許**再散布**（能不能放進複製包）？
   是否禁止快取或長期儲存（部分地理編碼服務如此）？是否**禁止用於訓練或處理
   AI／LLM**？最後這條在你的流程會把資料丟給 LLM 時是硬限制。
4. **速率限制**：文件寫多少、超過會回什麼（429？）、免金鑰與有金鑰的額度差多少。
   大量取數改走官方批次檔，不要用 API 硬刷。
5. **版本可追溯**：回應或文件有沒有版本號、資料更新時間、修訂歷史（vintage）？
   只給 `latest` 別名的，記下它**當下解析到的具體版本**；只有「當下狀態」、
   沒有歷史版本的來源，做縱貫研究就得自建定期存檔。
6. **穩定性**：路徑有沒有版本號（`/v1/`、`/v2/`）？有沒有棄用公告與遷移指引？
   主機搬過家的服務，清單上的連結常常還指向舊址。
7. **引用方式**：機構全名、資料集名稱或代碼、版本、擷取日期、URL；
   有資料集 DOI 就引 DOI。查不到官方建議格式時，依 APA 7 的資料集格式自組，
   並在資料附錄寫明查詢參數。
8. **可重現性**：查詢參數完整記錄（含預設值）、保留原始回應檔與雜湊、
   記錄抓取日期——總體統計與即時名單都會被修訂或覆寫。

## 四、判定「端點壞了」之前的區辨順序

核心紀律：**沒拿到證據是「未知」，不是「沒有」。** 看到錯誤碼或空結果時，依序排除：

| 順序 | 先懷疑 | 典型症狀 | 處置 |
|---|---|---|---|
| 1 | 本機環境 | 憑證錯誤、連線逾時、公司或校園代理攔截 TLS | 換網路或請 IT 確認；**不要關閉憑證驗證** |
| 2 | 必要標頭 | 403／404，而官方文件要求特定 User-Agent 或 Accept | 依文件補標頭再試 |
| 3 | 參數格式 | 400，或 200 但結果是空的 | 檢查日期格式、代碼體系（國碼、產業碼）、大小寫 |
| 4 | 權限 | 401／403，或被轉址到「缺少金鑰」說明頁 | 標「需註冊」；不借用他人金鑰、不繞道取數 |
| 5 | 服務本身 | DNS 查無主機、301 轉到遷移說明、文件標示停用 | 到這一步才判定失效，再去找官方後繼服務 |

**內容驗收比狀態碼重要：**

- **200 不等於成功。** 成功的判準是「回傳含預期欄位、非空、數值落在合理範圍」。
- **200 但空陣列**：回到上表第 3 步，**不要直接寫「該來源查無資料」**——
  代碼體系用錯時，很多 API 回空但不報錯。
- **200 但內容是 HTML 說明頁或驗證頁**（如 "Just a moment..."、"Attention required"）：
  那不是資料。用預設會跟隨轉址的客戶端時，被轉到說明頁一樣拿到 200。
  驗證頁代表站方要求人工，停止自動化，不換 UA、不換代理去繞。
- **首頁、hello、whoami 這類端點回 200**，只證明主機活著，不證明資料端點免金鑰可取。
- **只對暫時性失敗重試**（逾時、5xx、429），而且要退避；永久性失敗
  （404 路徑錯、401 要金鑰、DNS 不存在）重試沒有意義，只會增加站方負擔。

## 五、健康狀態標註詞彙（寫進目錄時統一用）

| 標註 | 意義 |
|---|---|
| ✅ 已實測可取數（日期） | 實際拿到含預期欄位的非空資料 |
| 🔑 需註冊 | 401／403／轉址到金鑰說明頁；未註冊、未測取數 |
| 🧩 需特定標頭／參數 | 補齊後可取數；陷阱要寫明 |
| ⏳ 暫時不可達（日期） | 逾時或 5xx，單次結果不足以判死 |
| 🚚 已遷移 | 301 到遷移說明或後繼服務 |
| ❌ 失效 | DNS 不存在、官方公告停用 |
| ⚠️ 待確認 | 未實測，或證據互相矛盾 |

規則：狀態只能靠「實際拿到的證據」升級；⏳ 與 ⚠️ 不得算進「可用來源」的數字裡。

## 六、用途分級（准入結論）

| 等級 | 條件 | 可以拿來做什麼 |
|---|---|---|
| A 主資料 | 一手產生者＋授權明確允許研究＋版本可追溯＋已實測 | 進論文主分析，引用產生者 |
| B 交叉核對 | 可信但有一項不足（例如只有 http、或是揭露來源的包裝層） | 穩健性檢驗、抽樣核對 |
| C 線索 | 個人專案、條款不明、未揭露來源 | 只用來找到「一手源在哪」 |
| D 不用 | OAuth 帳號資料、條款禁止你的用途、要繞過驗證才拿得到 | — |
