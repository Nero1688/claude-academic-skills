# 推薦與迴避審稿人：規範、寫法與陷阱

本檔接在 SKILL.md Step 5 之後、投稿系統要你填「Suggested / Opposed reviewers」的那一刻。
它回答三個問題：誰**不能**推薦（利益衝突）、誰**適合**推薦（以及理由怎麼寫）、
迴避怎麼寫才不被讀成操弄。所有時窗與數量限制**以該刊當期作者指南與投稿系統欄位為準**；
本檔只寫出版倫理上普遍接受的層級。

為什麼要認真對待：推薦審稿人是投稿者少數能影響審查程序的地方，也因此是出版倫理
最敏感的地方。出版界已有因假審稿人身分（作者提供的信箱實際由作者本人或友人控制）
而大規模撤稿的案例；出版倫理組織（如 COPE）把操弄審查列為不當行為。一次操弄的代價
不是那篇稿件，是作者在該出版商所有期刊的信用。

---

## 一、利益衝突：誰不能推薦

| 關係 | 可否推薦 | 說明 |
|---|---|---|
| 共同作者（常見時窗為近 3–5 年；以該刊定義為準） | 不可 | 含正在合作但尚未發表的稿件 |
| 指導教授、指導過的學生 | 不可（不論年限） | 師生關係在多數期刊被視為永久衝突 |
| 口試委員、學位論文審查委員 | 不可 | 他們已看過研究內容並給過意見，等於已參與 |
| 同機構、同系所、同研究中心 | 不可 | 含即將加入或剛離開的機構（時窗以該刊為準） |
| 共同計畫主持人、同一補助案的成員 | 不可 | 補助機關的計畫成員名單可公開查到 |
| 曾對本稿件給過實質意見的人（研討會評論人、工作坊參與者） | 灰色地帶 | 部分期刊視為衝突；不確定就不推薦，或在理由欄揭露 |
| 致謝名單中的人 | 不建議 | 你在稿件裡感謝他，編輯會問為什麼 |
| 親屬、密切私人關係、財務關係 | 不可 | 自明 |
| 近期在同一期刊互審過對方稿件的人 | 不可 | 「互審圈」是編輯特別警覺的樣態 |
| 引用了對方很多篇文獻的學者 | 可 | 引用本身不是衝突；但不要為了討好而堆砌引用 |
| 立場與本文相反、可能批評本文的學者 | 可，而且常是好人選 | 若其批評被本文回應，編輯會更信任審查結果 |

自查方法：把候選人姓名拿去比對 (1) 自己近五年所有共同作者清單；(2) 學位論文口試名單；
(3) 補助案成員名單；(4) 稿件致謝與參考文獻中的私人關係。四項任一命中就換人。

## 二、誰適合推薦、理由怎麼寫

**挑選準則（同時滿足越多越好）**
1. 稿件**實質對話**的對象：你在引言與討論節挑戰、延伸或調和的那幾篇文獻的作者。
2. 方法專長對得上你的識別策略：交錯 DiD、IV、RDD 或事件研究——審稿人若不熟你的估計量，
   審查會失焦在他熟的地方。
3. 在目標期刊或同級期刊近年有發表，代表他熟悉該刊的期待。
4. 機構與地理分散：不要全部來自同一國家或同一學派。
5. 職涯中段為佳：資深學者常無時間，資淺學者可能過度謹慎；以該刊為準，這只是經驗法則。
6. 沒有第一節任何一項衝突。

**推薦人數**：依該刊欄位；常見為 3–5 位。少於要求會被系統擋、多於要求沒有加分。

**每位的資訊**：姓名、職稱、機構、**機構信箱**（從該學者的機構網頁或近期論文的通訊
資訊核對；不接受任何免費信箱）、一行理由。理由只寫事實：

> "Author of [Paper, Journal, Year] on [topic]; expertise in staggered difference-in-differences designs."
> 「〔期刊、年〕〈〔論文〕〉作者；專長為交錯採用的 DiD 設計。」

不寫的：「對台灣研究友善」「認識本文作者」「曾正面評論本文」——前者是情境複製訊號，
後兩者是利益衝突自白。

**驗證每一位**：機構網頁確認在職、信箱網域與機構一致、近三年有相關發表。若名單是
任何工具（含本 skill、含生成式 AI）產生的，逐一核對——工具會生成看起來合理但不存在的
姓名、職稱或信箱，一筆錯誤就足以讓編輯懷疑整份投稿。

## 三、迴避審稿人：正當理由與寫法

**正當理由（事實可陳述、編輯可查證）**
- 直接競爭：對方正以相同的專有資料或同一制度事件進行尚未發表的研究。
- 已公開的學術爭議：雙方曾在期刊上有公開的評論與回覆。
- 個人利益衝突：曾有僱傭、顧問或財務關係，或私人關係，使對方無法客觀。
- 先前審查中對方已自揭身分並表明立場（僅在確有其事時）。

**不正當理由（寫了等於自曝）**
- 「他會給負面意見」「他不喜歡台灣資料」「他的學派與本文對立」。
- 迴避整個機構、整個國家、整個方法陣營。
- 迴避你在稿件中批評的那幾篇文獻的作者——批評了人家又不讓人家審，編輯讀成心虛。

**寫法**：一行、事實、不評價。
> "Professor [Name], [Institution]: currently pursuing a closely related project using the same proprietary dataset (unpublished)."
> 「〔姓名〕教授（〔機構〕）：正以同一專有資料庫進行高度相關且尚未發表的研究。」

**數量**：常見 1–3 位；以該刊為準。編輯沒有義務照辦；迴避名單只是資訊。

## 四、陷阱清單（每一條都有真實撤稿或退稿的前例型態）

| 陷阱 | 為什麼致命 | 防線 |
|---|---|---|
| 提供非機構信箱（免費信箱、自建網域） | 假審稿人事件的共同特徵；多數投稿系統與編輯會直接剔除或懷疑 | 只填機構信箱，且核對網域 |
| 推薦後私下聯絡該學者「幫忙看一下」 | 破壞審查獨立性，屬操弄 | 推薦後零接觸；對方若主動提及，回覆「不便討論審查中稿件」 |
| 互相推薦（你推薦他、他推薦你） | 編輯可從系統看到樣態 | 不與任何人協調審稿人名單 |
| 推薦全部來自自己的研討會或同鄉圈 | 名單本身就是「小圈子」訊號 | 至少一半是你未曾見過面的學者 |
| 推薦主編或副主編的共同作者以求好感 | 不是衝突，但顯得投機；且該人可能因與編輯的關係被迴避 | 以稿件對話對象為準，不看編輯人脈 |
| 為了讓被推薦者高興而在稿件中堆砌其文獻 | 審稿人看得出來；且拉低文獻回顧品質 | 引用只依論證需要 |
| 名單由 AI 產生未核對 | 幻覺姓名、職稱、信箱 | 逐一上機構網頁核對 |
| 迴避名單過長或理由帶情緒 | 讀成想控制審查 | ≤3 位、事實句 |

## 五、台灣商管稿件在頂刊的常見落差→具體對策（審稿人名單版）

推薦名單是編輯第一眼看到的「作者自認的對話對象」。三個落差在名單上各有一個訊號。

### 落差 1：情境複製——名單全是台灣或華人學者、理由寫「熟悉台灣資料」

- **訊號**：五位推薦人全在台灣或以台灣資料發表為主；理由欄寫「熟悉台灣制度」。
  編輯讀成「作者認為只有懂台灣的人才會覺得這篇重要」。
- **對策**：名單以**機制**為軸——至少三位是你在引言挑戰或延伸的理論文獻的作者
  （不論國籍）、一位識別方法專家；若要放一位熟悉東亞制度的學者，理由寫「專長為
  控制股東與投資人保護制度的比較研究」而非「熟悉台灣」。
- **理由句式**：「Author of [paper] establishing [claim A] that our paper qualifies.」

### 落差 2：識別靠制度變革，但名單裡沒有人能評估識別

- **訊號**：推薦人全是主題專家（家族企業、ESG），沒有一位是 DiD／IV／RDD 的方法學者。
  編輯若自己找方法審稿人，那位審稿人會用最嚴的標準看你的平行趨勢。
- **對策**：主動推薦一位近年以交錯 DiD 或事件研究發表的應用計量學者，理由寫明方法
  專長；同時確保稿件已做完 `causal-inference-architect` 的
  `references/robustness-battery.md` 必做項——推薦方法專家而稿件沒做誠實區間，等於
  自請退稿。

### 落差 3：名單反映的是「誰會喜歡台灣的顯著結果」，不是「誰能判斷量級」

- **訊號**：推薦人清一色是發表過同方向結果的學者，理由暗示「立場一致」。
- **對策**：刻意納入一位發表過**相反或無效果**結果的學者——若你的經濟量級段與基準表
  能說服他，審查結論的可信度最高；理由寫「Author of [paper] reporting [null / opposite]
  result in [setting]; our benchmark comparison engages directly with this estimate.」

### 台灣特有的利益衝突盲點

- 口試委員、學位論文審查委員、共同計畫主持人在台灣常同時是同領域少數活躍學者，
  很容易被當成「自然人選」推薦——這三類全是衝突（第一節）。
- 同系所或同校不同系的學者：仍屬同機構，不可推薦。
- 曾在國內研討會擔任本文評論人：灰色地帶，保守做法是不推薦。

## 六、送出前檢查

- [ ] 每位推薦人已比對：近五年共同作者、口試名單、補助案成員、同機構——四項皆無命中
- [ ] 每位信箱為機構信箱，網域與機構網頁一致；姓名職稱已上機構網頁核對
- [ ] 至少三位是稿件實質對話的文獻作者、至少一位方法專家、至少一位非本國學者
- [ ] 理由欄只有事實句；無「熟悉台灣」「友善」「認識作者」
- [ ] 迴避 ≤3 位、理由為可查證事實、無情緒與學派字眼
- [ ] 推薦後不與任何名單上的人談論本稿件
- [ ] 名單若經任何工具產生，已逐一人工核對
