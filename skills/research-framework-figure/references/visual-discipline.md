# 視覺紀律（research-framework-figure ／ management-figure 共用）

畫圖前先讀這份。這不是美術品味，是「審稿人與口試委員一眼看不懂就會被扣分」的
實務紀律。`research-framework-figure`（理論架構圖）與 `management-figure`
（統計結果圖）雖然畫的內容不同，但兩者服務同一群讀者（Q1/ABS 期刊審稿人、
口試委員），所以共用同一套紀律，不各自發明一套。

## 一、密度與留白

1. **無陰影、無漸層。** 學術圖表不是簡報美術稿，陰影與漸層只會讓列印（尤其
   黑白列印）時的邊界模糊，且不傳達任何額外資訊。方框一律純色填白／單一
   邊框線，箭頭一律純色實線或虛線。
2. **密度上限（判準，非硬性規定，超過就該考慮拆圖或分層）**：
   - 單張圖節點（方框）數建議 ≤ 10 個；超過 10 個，讀者已經無法在合理時間
     內同時記住每個節點的角色。
   - 單張圖連線（含箭頭）數建議 ≤ 14 條；連線一多，交叉點會讓讀者分不清
     哪條線接到哪個框。
   - 若你的模型或流程天生就超過這個量級（例如 PRISMA 圖天生有 6 個主欄
     框＋3 個排除框，接近上限），優先用「主欄＋側欄」分層而不是把所有框
     擠在同一個視覺層級——這正是 `sample_flow` 兩個 mode 的版面設計理由。
   - 超過上限的因應方式：拆成兩張圖（如「總體架構圖」＋「H2 細節圖」），
     或把次要資訊挪到圖說 caption／內文表格，不要硬塞進一張圖裡。
3. **對齊網格。** 元素要對齊到看得出的網格線——同一欄的框左右邊界對齊、
   同一列的框上下邊界對齊，不要讓框自由散置（即使程式自動排版，也要在
   產圖後檢視是否有明顯沒對齊的框，人工微調 `style` 或座標）。

## 二、色彩：單一強調色 + 中性色

4. **單一強調色只留給讀者必須看到的那條關鍵路徑**（例如你的核心假說 H1，
   或 PRISMA 圖裡「最終納入」的那個框），其餘一律維持中性色（黑框白底、
   灰階線條）。強調色一旦超過一種，讀者就無法判斷「哪個才是重點」——這與
   「不做誤導性視覺」是同一件事的兩面：色彩不夠是看不出重點，色彩太多是
   看不出誰才是重點。
5. **色盤與 `management-figure` 共用同一套 Okabe-Ito 色盲友善色盤**，不重新
   發明另一套色碼（見 `management-figure/references/figure_style.md`）：

   | 用途 | 色碼 |
   |---|---|
   | 藍（預設強調色） | `#0072B2` |
   | 橘紅 | `#D55E00` |
   | 綠 | `#009E73` |
   | 粉 | `#CC79A7` |
   | 黃 | `#E69F00` |
   | 淺藍 | `#56B4E9` |
   | 灰（中性／非強調） | `#999999` |

   本技能（`research-framework-figure`）預設圖仍是純黑白線稿（投稿慣例，
   多數期刊架構圖不上色）；只有在使用者明確要求「標出關鍵路徑」或「口試
   簡報要上色」時，才從上表挑一色當強調色，且**只挑一個**。

   **色盲友善不等於對比足夠**：黃、淺藍、灰在白底的對比低於 3:1，不可當細線、
   資料點或文字色；七色轉成灰階後明度也很接近。實算數值與替代色見
   `management-figure/references/chart-honesty.md` 第四節。

## 三、每個節點都要有存在理由

6. **判準**：拿掉這個節點，論證會不會看不懂？會，就該留；不會，就該刪。
   常見違規：把「未使用的控制變數」畫進架構圖（那是結果圖或文字說明的事，
   見 `diagram-conventions.md` 第六節）、把 PRISMA 圖裡數量為 0 的排除類別
   也畫一個空框（沒有排除到任何記錄就不必畫該排除框，或用文字註明「無」
   而不是留一個空的方框佔位置）。
7. 這條同樣適用於 `sample_flow`：`attrition` 的每一步都應該對應論文方法論
   一節裡實際交代的一次篩選；不要為了「畫起來對稱好看」硬湊步驟數。

**移除測試四問**（第 6 條的完整版，畫完逐題問）：
- 能刪一個節點嗎？刪了讀者仍看得懂 → 刪。
- 能合併兩個節點嗎？兩個框總是一起出現、一起被討論 → 合成一框條列。
- 能刪一條線嗎？關係已由位置表達，或根本不是假說 → 刪（例：沒有設假說的外生變數
  相關雙箭頭）。
- 能刪一個標籤嗎？線型或形狀已經表達 → 刪；但 H 編號是對回內文的錨點，不刪。

## 四、標籤經濟

8. **框內文字建議不超過兩行。** 超過兩行就該精簡措辭，或拆成「主標籤＋
   副標籤」（例如主標籤「公司規模」、副標籤「（期末資產總額取自然對數）」
   放小字或放註腳，不要整句塞進框內把框撐得又高又寬）。
9. 條列項目（M 框、控制變數框、PRISMA 排除理由框）本身允許多行，但**每一
   行**要遵守上一條的兩行上限；一行排除理由寫成一整句方法論說明，不如拆
   成「理由關鍵詞（n=…）」，細節留給內文或表格。

## 五、畫圖前，先回答三個問題（借用「先定調再產出」的精神）

畫任何一張圖之前，**先能回答以下三題**，答不出來代表規格還沒想清楚，回頭
跟指導教授或審稿意見再對一次，不要急著開始排版：

1. **這張圖要讓審稿人在 5 秒內看懂什麼？** 一張圖只服務一個核心訊息（例如
   「H2 是本研究的直接效果路徑」或「最終樣本是如何從全樣本篩出來的」）。
   若答案是「好幾件事」，代表這張圖該拆成兩張。
2. **這張圖預計放進投稿或論文的哪一節、扮演什麼論證角色？** 是研究架構圖
   （第三章、方法論開頭），還是文獻回顧的篩選流程圖（PRISMA，通常放在
   文獻回顧或方法論一節，且期刊常要求附在正文或附錄），還是樣本描述
   （attrition，通常放在資料與樣本一節，緊接在敘述統計表之前）？版式與
   放置的位置要對得上，不要把 PRISMA 圖放進論文的研究架構一節。
3. **如果印成黑白，這張圖還讀得懂嗎？** 多數期刊仍是黑白印刷，審稿人也常
   用黑白印出來看。若顏色是唯一的區分手段（例如用顏色分「假說路徑」與
   「控制變數」），一旦印成黑白就會全部變成同一種灰階線條而看不出差異。
   **一定要加形狀或線型當備援**——本技能家族的既有慣例正是如此：假說
   路徑一律實線、控制變數一律虛線，`sample_flow` 的主欄與排除欄則用
   「位置（主欄置中／排除欄在側）＋方向（向下／向右）」而非顏色來區分，
   即使黑白列印也看得出結構。

## 六、字型紀律（與既有慣例一致，不重新發明）

10. 中文＝標楷體（`DFKai-SB`／`BiauKai`），英數＝Times New Roman，這是
    CLAUDE.md 的硬規則，SVG 端寫成 `font-family="Times New Roman, DFKai-SB,
    BiauKai, serif"`（西文排前面），PPTX 端西文走 `run.font.name`、中文走
    `a:ea` 東亞字型設定（見 `framework_figure.py` 的 `set_font()`）。
11. **字型缺漏要誠實告知，不假裝已套用。** 若檢視端沒有標楷體，中文會
    fallback 成系統預設字型；產出後務必在有字型的機器上確認一次，交付
    訊息裡明講「本環境／檢視端無標楷體，實際顯示為 ○○，投稿前請於有
    字型的機器確認」。這是 `research-framework-figure` 與 `management-figure`
    的共同紀律，不因版式不同而有例外。

## 七、連線衛生（架構圖與流程圖）

連線是讀者追路徑的唯一線索；以下任一條破功，審稿人就得用手指描線。

12. **標籤不壓線。** 假說標籤的白底遮罩與線之間要有看得見的間隙（約 6–10 px，
    印出約 1–2 mm），遮罩不可蓋到線；垂直線的標籤放在線的側邊。斜線上的標籤要
    往線的**垂直方向**外移，不是直接往上移——往上移的遮罩常把斜線蓋掉一段。
    不用直排文字。
13. **線不重疊。** 兩條線不共用路徑、不疊在一起；平行的線至少隔開約 12 px。非交叉
    不可時，在其中一條線上做小拱橋（跨線符號）；交叉一多，就是版面該重排。
14. **同一邊分散接點。** 同一個框的同一邊有 N 條線進出時，各有獨立接點，第 k 條放在
    該邊 k/(N+1) 處、相鄰至少隔約 12 px，不讓兩支箭頭擠在同一點。
15. **線不穿框。** 線不可從非起訖的框後方穿過（例：X→Y 直接效果線穿過 M 框或控制框），
    一律改版面或繞線。通用繪圖規範允許「不可避免時改用虛線穿過」，但學術架構圖的
    虛線已代表控制變數，**本家族不採這個例外**。
16. **遮罩不蓋框。** 繪製順序是「線 → 標籤 → 框」，標籤遮罩若壓到之後才畫的框，會被
    框蓋住只剩半個字；標籤要放在線段穿過空白處的那一段。
17. **折線或斜線，一張圖只用一種。** 流程類（研究流程、樣本流程、決策流程）一律直角
    折線、轉角小圓角，不畫斜線；假說路徑圖沿用學界慣例的直線斜箭頭（中介三角形），
    不強制直角化。調節箭頭落在路徑中點的規則不變（見 `diagram-conventions.md`）。

> **產生器現況**（2026-10-08 修正並以三個 example 前後截圖比對確認）：假說標籤改為沿線的
> **法線方向**外推（水平線放上方、垂直線放右側、曲線取貝茲中點），遮罩與線留 4 px 間隙，
> 斜線不再被蓋掉一段；PPTX 匯出的標籤位置跟著 SVG 座標走。仍存在的取捨：
> `mediation_dual_controls` 中 M 的控制變數虛線會跨過 H2 主路徑——屬版式取捨，交付前目視
> 確認，口試版可改用 `output-tiers.md` 的平衡層級。

## 八、圖例、旁註與強調

18. **圖例只列用到的編碼。** 實線＝假說路徑、虛線＝控制變數——圖上有幾種就列幾種，
    不多不少。圖例放圖的底部一條（或直接寫進圖註），不浮在節點之間。
19. **旁註（callout）**：期刊版不用，該說的寫進圖註（「註：…」）。口試／海報版最多 2 個，
    放在圖的邊緣、以細虛線引線指向目標（與實線箭頭區隔），引線不可跨過主路徑。
    能直接標在元素上的，就不要用旁註。
20. **強調的是論證，不是最大值。** 強調色給圖說要講的那一條路徑或那一格（核心假說、
    最終納入框），不是自動給係數最大或最顯著的那個。
21. **框寬最多兩種。** 同層級的框用同一寬度；寬度五花八門會被讀成「重要性不同」。

## 九、產圖後的自我檢查（濃縮版）

- [ ] 無陰影、無漸層
- [ ] 節點數／連線數在密度上限內，超過已拆圖或分層
- [ ] 元素對齊到看得出的網格；同層級框寬一致（最多兩種）
- [ ] 強調色只有一種（或完全不上色，維持黑白線稿），且給的是論證焦點
- [ ] 移除測試四問都問過（節點／合併／線／標籤）
- [ ] 框內文字不超過兩行
- [ ] 能一句話說出這張圖的 5 秒訊息、放進論文哪一節
- [ ] 印成黑白仍看得出區別（顏色有形狀／線型備援）
- [ ] 標籤不壓線、不蓋框；線不重疊、不穿框；同一邊接點分散
- [ ] 流程類用直角折線、路徑圖用直線，一張圖只用一種
- [ ] 圖例只列用到的編碼；期刊版無旁註，口試／海報版旁註 ≤2
- [ ] 已定用途與細節層級；平衡／精簡版附省略帳（見 `output-tiers.md`）
- [ ] 字型已確認（或誠實告知 fallback 狀況）
