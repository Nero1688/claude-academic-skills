# 複雜揭露文件的前處理(文字分析的第 0 步)

Step 1(語料與構念)假設你手上已經有「乾淨的文字」。但財金研究常見的語料——
**10-K / 年報、ESG 永續報告書、公開說明書、法說會簡報、政府表單**——是版面複雜的
PDF/HTML(多欄、密集表格、圖表、頁首頁尾、掃描頁)。用 `pdftotext` 直抽,表格會被
壓平、多欄會交錯、頁碼混進正文——**髒進髒出,後面的斷詞與情緒分析全被污染**。
所以在 Step 1 之前,先把文件洗成乾淨的結構化文字。

## 何時需要這一步

| 文件類型 | 直抽風險 | 要不要版面感知抽取 |
|---|---|---|
| 乾淨學術 PDF(單欄、少表格) | 低 | 不用,內建 pdf skill / bilingual-paper-reader 即可 |
| 10-K / 年報(多欄+密集財務表) | 高 | **要** |
| ESG / 永續報告書(圖文混排、表單) | 高 | **要** |
| 掃描版舊文件(無文字層) | 極高(需 OCR) | **要**,且需 OCR |
| 法說會逐字稿(純文字) | 低 | 不用 |

## 版面感知抽取:概念與工具

核心概念(借鑑 [KingsleyOWO/Semark](https://github.com/KingsleyOWO/Semark),Apache 2.0):
**用版面分析 + OCR 把複雜文件轉成「保留語意結構的 markdown」**——表格還原成 markdown
表格、多欄依閱讀順序串接、圖表/流程圖轉成結構化描述、並保留 source map(哪段文字來自
原文哪頁),而非一坨壓平的純文字。

工具選項(本 skill 只給概念與判準,不引入依賴):
- **MinerU 類版面感知抽取器**(Semark 的底層):對學術/財金複雜 PDF 的表格與多欄還原較好。
- **內建 pdf skill**:一般 PDF 與 OCR 夠用,是輕量首選;複雜表格才升級到 MinerU 類工具。
- 授權注意:Semark 本身 Apache 2.0,但其鏈上的 **PyMuPDF/MuPDF 是 AGPL-3.0**——
  若你要把這類工具**併進會散布的程式碼**,先確認授權相容;只是「自己跑來產出乾淨文字」
  則無此顧慮。

## 前處理的紀律(沿用家族精神)

1. **抽取品質要驗**:抽完抽樣核對——表格有沒有錯位、多欄有沒有交錯、頁首頁尾有沒有
   混進正文。髒抽取比沒抽取危險(你不會發現情緒分數是被頁尾污染的)。
2. **保留 source map**:每段文字記來源(檔名、頁碼)——呼應 multi-source-data-integrator
   的來源譜系,也讓抽取錯誤可回溯。
3. **PII 遮罩**:揭露文件含自然人姓名/員工編號/信箱,抽取階段就遮罩(Semark 內建此步,
   概念值得沿用),與本 skill Step 1 的語料去個資一致。
4. **語言與術語**:繁中/財經術語在抽取階段就要保住,別被 OCR 拆錯(公司名、會計科目)。
5. **可重現**:抽取參數(工具、版本、設定)寫進方法節與複製包——洗文件也是 pipeline 的一環。

## 接回主流程

乾淨結構化文字 → Step 1(語料與構念效度)→ Step 2(方法階梯)→ …
表格類資料若是研究變數(如財報數字),抽出後走結構化資料鏈(multi-source-data-integrator /
r-spss),不當文字處理。
